A* Path Planning Implementation
I implemented A* pathfinding over a hex-tile map, the algorithm a unit uses to find the shortest route from one tile to another while avoiding obstacles.
  • Turned the raw tile map into a searchable graph: each tile became a node, and I worked out the adjacency rules for hex tiles (which has six neighbors instead of a grid's four) so the search knew where it could legally move.
  • Wrote the A* search itself, using a heuristic to estimate the remaining distance to the goal so it explores promising tiles first and reaches the answer far faster than a blind search.
  • Validated it against simpler algorithms like BFS on the same maps to confirm A* returned the same optimal path while touching fewer tiles, and tested edge cases like blocked-off goals and tie-breaking between equal-cost routes.
Flocking Algorithm Implementation
I built a flocking system, the kind of emergent group movement you see in a flock of birds or a school of fish, where each agent (a "boid") only follows three simple rules but the group as a whole moves believably. (This is the same model running behind the homepage background.)
  • Alignment: each boid steers toward the average heading of its nearby neighbors, so the group tends to travel in the same direction.
  • Cohesion: each boid steers gently toward the center of its local group, which keeps the flock together instead of scattering.
  • Separation: each boid steers away from any neighbor that gets too close, the rule that prevents collisions and gives the flock its spacing.
  • The interesting part is the blend: I weighted and combined these three competing forces each frame so no single rule dominates, then tuned the weights and neighbor radius until the motion looked natural across different crowd sizes.
