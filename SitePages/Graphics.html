List of Contributions:
Sprite Rendering and Blitting
I built 2D rendering from scratch in C++, drawing images to the screen one pixel at a time without a graphics library doing the work for me.
  • The screen is really a 1D array of pixels, so I wrote the indexing math to map an (x, y) coordinate to the right spot in that array, the foundation everything else is drawn on.
  • Implemented alpha blending so sprites with transparency layer correctly over what's already on screen, mixing each pixel's color by its opacity instead of drawing a hard rectangle.
  • Wrote and optimized the blit routine that copies a sprite's pixels onto the screen buffer, which is the per-frame hot path, so it had to stay fast.
Environment Setup and Sprite Animation
Building on the sprite renderer, I put together an actual animated scene to prove the system worked in practice.
  • Created a tiled background by repeating a single grass texture across the whole screen, the standard trick for filling a large area cheaply from one small image.
  • Scattered tree sprites at randomized positions so the environment looked organic instead of laid out on an obvious grid.
  • Wrote a small animation system that cycles through a sequence of fire frames on a timer, turning a set of still images into a looping flame effect.
DirectX 11 and Gateware: Cube Rendering with Camera Control
I moved from software 2D into hardware-accelerated 3D, rendering a textured cube you can fly around using DirectX 11 and the Gateware framework.
  • Wrote vertex and pixel shaders, the small programs that run on the GPU to position each corner of the cube and decide the color of every pixel it covers.
  • Set up a constant buffer to hand the world, view, and projection matrices to the GPU each frame, which is how the CPU tells the shaders where the camera is and how the scene should be projected onto the screen.
  • Built a camera system with movement controls so you can navigate around the cube in 3D space, and used Gateware to handle the window and keyboard input.
