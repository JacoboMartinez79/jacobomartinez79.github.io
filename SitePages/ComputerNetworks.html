Computer Networks Server/Client Project

C++ | WinSock API

List of Contributions:

Server Implementation

I built the server side of a real-time chat system in C++ on top of the raw WinSock API, which meant working directly with sockets instead of a higher-level networking library.
  • Used a multiplexing model (a single select() loop) so one thread could watch every connected socket at once, accepting new clients and reading incoming messages without blocking. The server holds up to five simultaneous connections and broadcasts each message out to the rest.
  • Designed a simple serialization format so messages could be packed into a byte buffer to send over the wire and unpacked on the other end, and persisted the chat log to a text file so history survives between sessions.
  • Handled the messy realities of network code: partial reads, clients dropping without warning, and cleaning up sockets so a single disconnect never takes the whole server down.

Client Application

I wrote the matching client in C++, the program a user actually runs to join the chat and talk to the server.
  • Built a console interface that walks the user through connecting: it asks for the server's IP and port, opens the socket, and gives clear feedback when a connection succeeds or fails.
  • Implemented real-time messaging by listening for incoming data while still letting the user type, so messages from other clients appear the moment they arrive rather than only after you hit enter.
  • Made the client fail gracefully when the server goes away mid-session: instead of crashing, it detects the dropped connection, tells the user, and exits cleanly.
